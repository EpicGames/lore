- `lore-revision`: Fixed `lore file dirty` replacing a staged change with the change it marks, so the commit took something other than what was staged: a staged deletion of a file written again became a modification, a merge's deletion past the view included. A staged change stands until it is unstaged, and the mark only notes that the path changed. A new file or directory marked dirty at the path of a node staged for deletion is added beside it, and `lore status` and `lore unstage` of that path, or of a path below it, take the new node, the deletion staged until its directory is unstaged.
- `lore-revision`: Fixed `lore commit` failing with a file-not-found error where a staged file was removed from the working tree after it was staged. A staged file or directory the working tree no longer holds at commit time is committed as deleted, and one staged as added is committed as nothing, and the same holds for a staged file whose path now holds a directory, which stays untracked. A directory that is gone goes with everything in it, files that were not staged included, as it does where a file now stands at its path, which stays untracked; so does a directory staged only because a staged move took a file out of it. A directory the working tree still holds stays, an added one committed empty, and so does one holding something the view excludes or a link's mount. A file or directory staged as moved that is gone from its new path and back at its committed path stays there as committed instead, whatever it holds, with what moved with it, the move left out; a later scan marks an edit in it. A file or directory added in such a directory, or copied into it, and staged is left out and stays marked dirty as added where the directory went back. What another staged move took into it, or renamed inside it, is committed as gone, unless it too is back at its committed path, and a deletion staged in it is committed. The commit is refused where such a directory holds a link with a staged change inside it; stage the move back, or unstage it. Don't commit after merging, reverting or cherry-picking in an instance cloned or synced with `--root-file`, or cloned or switched with `--bare`: the commit can delete a directory the instance never had on disk, with everything in it.
- `lore-revision`: Fixed `lore file dirty` of a directory removed from the working tree, below which a deletion was staged, staging the deletion of the whole directory. The mark leaves what was staged as it was. A commit while the directory is still gone deletes all of it, as it does any directory the working tree no longer holds.
- `lore-revision`: Fixed `lore file dirty` of a directory removed from the working tree committing a new file in it that was only marked dirty, and committing a file that `lore file dirty move` moved into it inside it, or dropping that file where the directory was new. Such a file goes back to its committed path, marked deleted there. A removed directory that `lore file dirty move` moved goes back the same way, what the view excludes below its committed path left unmarked, and a file a staged move took into a new directory leaves with the directory, as a commit of the directory gone takes it.
- `lore-revision`: Fixed a deletion marked dirty in a directory that `lore file dirty move` moved being lost: marking the removed file dirty after the move ignored it, and a commit that left the move out marked the file moved.
- `lore-revision`: Fixed `lore file dirty move` into a new directory at the name of a file staged for deletion putting the moved file below that file, so the commit deleted it. The directory is added beside the deleted file, and a move below a file is refused.
- `lore-revision`: Fixed a staged move, by `lore stage move` or the C API, of a file out of a directory that `lore file dirty move` moved committing the directory's move as well. The directory's move stays marked dirty and unstaged. `lore stage move` marks what it moves dirty, as the C API's move does.
- `lore-revision`: Fixed `lore commit` taking the move of a directory that `lore file dirty move` moved after a staged file was moved out of it, though it held no staged change any more.
- `lore-revision`: Fixed `lore commit` storing a revision whose directory addresses did not match what they hold, where a directory a staged move took a file out of held a new file that was removed and marked dirty again.
- `lore-revision`: Fixed `lore file dirty move` of a directory holding a staged change marking the files moved with it as moves not staged, though the commit takes them with the directory. The directory's whole move is staged, as a stage inside a moved directory stages it, and stays staged once that change leaves the directory. A staged file moved into a directory `lore file dirty move` moved, by either move command or the C API, stages the directory's whole move the same way.
- `lore-revision`: Fixed `lore reset` of a path whose committed file is marked deleted beside a file `lore file dirty move` or `lore file dirty copy` put there acting on which of the two was marked first: it wrote the committed file over a moved one, or left a copy in place. The reset refuses where either is staged, discards a copy or an add and restores the committed file, and leaves a move as it leaves every move.
- `lore-revision`: Fixed `lore link add`, `lore link update` and `lore link remove`, `lore file obliterate`, a merge, a resolve, a sync and `lore unstage` staging the move of a directory that `lore file dirty move` moved, where they staged something inside it, without the files that moved with it. The directory's whole move is staged, as a stage inside it stages it.
