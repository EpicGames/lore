- `lore-revision`: Under a view, `lore clone`, `lore sync`, `lore branch switch`, `lore branch merge`, `lore revision cherry-pick`, `lore revision revert`, `lore sync --view`, `lore reset`, `lore layer add` and `lore link add` no longer create a directory the view excludes that Lore walks only because a re-inclusion could match below it, such as `Engine/` under `/*` and `!*/Saved/Config/` where the repository holds no `Saved/Config` below it, unless something below it is kept. Every directory the view keeps is created, whatever it holds, so under `/a/*` or `/a/**` the directory `a` is. A view that excludes everything and re-includes files by extension now creates only the directories holding a kept file: of the 5.55 million directories a compile workspace view with 110 rules created, about 140 thousand hold one. `lore sync --view` removes a directory the new view excludes once the files it held leave and it is empty, and a dry run of `lore clone` lists the directories the clone creates. An instance cloned under a view by a nightly build from 22 November 2026 on can lack a directory the view keeps but nothing in which it keeps, such as `a` under `/a/**`, or `bin` holding only `.bat` files under `*.bat`: `lore status --scan` and `lore dirty .` mark it deleted, and staging the mark stages its deletion with everything below it, which committing removes from the revision. Before staging, run `lore reset` on each directory `lore status --scan` lists as deleted, which creates it again.
