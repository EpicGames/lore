- `lore-client`: `lore service set-external-directory <path>` moves every virtual instance's external directory to a new external root, and records it in `external-root` in the global data directory. It renames the external root within its volume, and copies it to another volume. It stops the running service, holds its socket while the external root moves, starts the service again, and leaves a link at the default location for older versions. `--adopt` points the setting at a copy of the external root, or writes a lost `external-root` again, and `--abandon` gives up an external root on a failed volume for a new, empty one. `--dry-run` reports what the move would do, and Ctrl-C before the final switch undoes the move. See the how-to page Move the external directories of virtual instances.
- `lore-client`: A copy refuses what it can't keep rather than copy it differently. On Linux and macOS it keeps each file's contents, holes, owner, permissions, extended attributes, access control lists and times, and refuses a hard link, a socket, a pipe or a device, an entry marked immutable or append-only, and an extended attribute the target's file system doesn't support; other file flags, such as those of a hidden or compressed file, aren't copied. On Windows it carries data, alternate data streams, the owner, the group, the access control list and sparse ranges, keeps attributes, and refuses reparse points, files with more than one link, and entries with an attribute it can't keep as it is, such as encryption or compression; it leaves out audit entries, which a process reads only with `SeSecurityPrivilege`, and object IDs, which identify a file on its volume rather than what it holds. On Linux, a security label or file capability that the system's policy refuses to set takes the value of its new location, and the command names it in one warning. An entry whose group the user isn't a member of takes the group of its new location, and the command reports how many did. Only the user can reach the new external root, so that group gives no one else access. A copy needs room for the external directories on the target's volume, and on Windows a volume that holds access control lists, alternate data streams and sparse files. After a copy, each FUSE instance reads and hashes the files in its overlay again at its next scan or commit.
- `lore-capi`: `lore_service_set_external_directory` and `lore_service_set_external_directory_async` run the same command, with `lore_service_set_external_directory_args_t`.
- `lore`: A starting service finishes or undoes a move of the external root that was interrupted, before it mounts anything, and removes the old directories a move left, in the background.
