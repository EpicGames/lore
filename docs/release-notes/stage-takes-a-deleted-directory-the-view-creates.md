- `lore-revision`: Fixed `lore stage` in an instance with a view leaving unstaged the deletion of a directory the instance creates under its view, such as `a/b/` under `**`, `!/a/b/` and `/a/b/*`, which `lore status` listed as deleted and `lore commit` could never record. Staging now stages the directory as deleted, and everything below it goes with it as part of its deletion, the files the view leaves out included, which committing removes from the revision. The same holds for every directory the view keeps, whatever it holds: deleting `src/` under `*.bat` stages `src/` as deleted, and `src/y.bat` goes with it beside `src/x.txt`, and deleting `bin/`, which holds only `bin/y.bat`, stages both as deleted. For such a deletion, `lore stage` reports each file the view shows below the directory as deleted, with a file stage event; the files the view leaves out go with the directory without being reported. Such a directory holding a change a pending merge staged stays until the merge is committed, which keeps the change; `lore status --scan` then lists the directory as deleted, and `lore stage` takes it. `lore unstage` takes the deletion back, and `lore reset` creates the directory again. In a repository that holds a link, staging still deletes only what the view keeps below such a directory, and the directory stays while it holds a link or anything the view leaves out.
