- `lore-revision`: Fixed `lore file dirty move` onto a path that already holds a file or directory leaving both under one name, the old one neither deleted nor marked. The old file or directory is marked deleted, with what it holds, and the moved one stands beside it under the name, as `lore stage move` stages the old one's deletion; one holding a staged change is staged for deletion, one only marked added there is dropped, and one `lore file dirty move` moved there goes back to its committed path, marked deleted there, beside whatever holds that path now. A move onto a link's mount is refused, as is one onto a directory that cannot leave the name: one `lore file dirty move` moved there whose committed directory now lies inside it, or one only marked added that holds a file or directory moved there whose committed path another node only marked dirty holds. `lore stage move` takes such a move.
- `lore-revision`: Fixed `lore commit` storing a revision that holds two files or directories under one name, where one is staged and the other's deletion is only marked dirty, which a later sync of the revision fails on: after a file was replaced by a directory, or a directory by a file, and the new one staged, or a file was moved with `lore file dirty move` onto one marked deleted and then staged. The deletion is committed with the staged one, with what it holds, in layers and links as well.
- `lore-revision`: Fixed `lore commit` of a directory's deletion, or of a file staged where the directory stood, after `lore file dirty move` took a file out of the directory and before that move was staged, recording the moved file in the revision's changes without its deletion. The file is recorded deleted with the directory, and the file at its new path is marked added.
- `lore-revision`: Fixed `lore commit` of a directory's deletion staged after `lore stage move` took a file or directory out of it, where the working tree held the file or directory at its committed path again and not where it moved. The revision's changes left out the file's deletion, and recorded the directory as unchanged, without the deletion of what it held. Each is recorded deleted with the directory.
- `lore-revision`: Fixed `lore status`, `lore file info`, `lore unstage` and `lore diff` of a path whose name a file marked dirty as deleted and another file both hold taking the deleted file where it came first. They take the other file, as they do beside a file staged for deletion.
- `lore-revision`: Fixed `lore status` of a name a file moved with `lore file dirty move` took from another reporting a modification and an addition, or a modification and a deletion, instead of the other's deletion and the move, and `lore status --scan` then dropping the move or marking the moved file deleted in the other's place.
- `lore-revision`: Fixed `lore file dirty` of a path that `lore file dirty move` moved a file or directory away from marking the moved one modified, or deleted, in place of what the working tree holds at the path: a new file written there is marked added beside the moved one, whose move stands, and a path the working tree lacks marks nothing.
- `lore-revision`: Fixed a directory's move through the C API taking a deletion only marked dirty off a file below it, and recording a file only marked dirty as added, below it or moved itself, as a move. Both are kept as the CLI's moves keep them.
